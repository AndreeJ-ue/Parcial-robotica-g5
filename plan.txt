PLAN — Estado del proyecto (arquitectura por estaciones)

1. Objetivo
Tener la cadena completa voz/texto -> decisión -> brazo sin datos de calibración puestos a mano
en cada corrida: los datos ya calibrados viven fijos en el código y la visión es un nodo ROS
aparte. La cámara va MONTADA EN EL BRAZO, así que la percepción solo es válida con el brazo en
POSE_BUSQUEDA.

2. Arquitectura (ítem 2)
   cámara (/image_raw) -> percepcion_camara -> /objeto_detectado  (JSON: {estación -> color})
   /orden_decidida    -> orquestador -> goals move_arm -> broker -> /joint_states -> brazo
   Regla dura: SOLO el broker publica /joint_states.

   Módulos (src/arm_broker/arm_broker/):
   - estaciones.py        FUENTE ÚNICA DE VERDAD: 4 ROIs (cuadrantes de la imagen) + pose de
                          agarre por estación (grados).
   - poses.py             poses base + a_radianes() + trozar() + planes (secuencia_*).
   - percepcion_camara.py NODO ROS: mide el color de cada estación y publica el mapa.
   - orquestador.py       decisión -> rechazo previo -> cola -> POSE_BUSQUEDA -> mapa -> planes.
   - validez.py           reglas duras compartidas (acción válida + vetadas).
   - cliente_laya.py      HTTP contra LAYA, con permitido fail-safe y catálogo cerrado.
   - clasificador_palabras_clave.py  respaldo local determinístico.

4. Troceado
   El broker valida el paso con su paso_max_rad (default 1.2). El orquestador trocea cada tramo con
   poses.trozar(..., paso_orquestador_rad=1.0) para no recibir rechazos con causa 'paso'.
